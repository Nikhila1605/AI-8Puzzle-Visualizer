Algorithm 1 — Breadth-First Search (BFS)

The 8-Puzzle problem

The 8-puzzle is a 3 × 3 frame holding eight numbered tiles and one empty square. A tile next to the empty square can slide into it. Starting from a scrambled initial state, the task is to reach a chosen goal state using as few slides as possible.

In AI it is treated as a state-space search problem: every arrangement of the tiles is a state, each slide is an action costing 1, and the solver must find a sequence of actions that leads from the initial state to the goal. It is simpler to think of the blank as the thing that moves (Up, Down, Left or Right), so a state has 2, 3 or 4 successors depending on where the blank is.

Of the 9! = 362,880 possible arrangements, only half can reach any given goal, so each search space has 181,440 reachable states. This site solves the puzzle with Breadth-First Search, which looks at all states one move away, then all states two moves away, and so on, and therefore returns a solution with the minimum number of moves.

    Algorithm information

    Breadth-First Search

    Description

    Breadth-First Search is an uninformed (blind) search strategy: it uses only the problem definition and has no estimate of how close a state is to the goal. It expands the shallowest unexpanded node first, so the search grows outward in layers — every state at depth 1, then every state at depth 2, and so on.

    Working principle

    The order comes from the data structure. BFS keeps its frontier in a FIFO (first-in, first-out) queue. Newly generated children join the back; the node taken out for expansion always comes from the front. Since all depth-k nodes enter the queue before any depth-k+1 node, they also leave first.

    For the 8-puzzle, different move sequences often lead to the same board, so the program also keeps a visited set. A state is added to it as soon as it is generated; any later copy is skipped. Each stored node remembers its parent, so once the goal is found the path is rebuilt by following parents back to the start.

    Pseudocode (as implemented in js/bfs.js)

    BFS(start, goal)
  nodes   ← [ node(start, parent = none, depth = 0) ]
  visited ← { start }
  if start = goal: return path(start)
  head ← 0                             // front of the FIFO queue
  while head < length(nodes):
      current ← nodes[head]; head ← head + 1      // dequeue
      for each (state, move) in SUCCESSORS(current):
          if state in visited: continue  // repeated state
          child ← node(state, parent = current, depth = current.depth + 1)
          append child to nodes; add state to visited     // enqueue
          if state = goal: return PATH(child)            // early goal test
  return failure                         // frontier empty

    How the numbers are counted

    • Generated – the start node plus every successor created by a legal move, including repeats that were then skipped.
    • Expanded – nodes taken from the front of the queue whose successors were generated. The goal is tested when generated, so it is never expanded.
    • Frontier / Explored – the nodes still waiting in the queue / the nodes already expanded. Together they are the visited set.
    • Depth = path cost g(n) – every move costs 1. Max depth is the deepest node generated.
    • Memory (approx.) – BFS keeps every stored node until the end (needed to rebuild the path), so memory ≈ stored nodes × ~200 bytes.

    Properties

    CompletenessYes – if a solution exists at finite depth and the branching factor is finite
    OptimalityYes, when every action has the same cost (true here: each move costs 1)
    Time complexityO(bd) nodes generated
    Space complexityO(bd) – frontier and explored nodes are kept

    b = branching factor (2, 3 or 4 for the 8-puzzle depending on the blank's position, roughly 3 on average), d = depth of the shallowest solution. With repeated states removed, the search can never store more than the 181,440 reachable states.

    Advantages

    • Always finds a solution when one exists.
    • The first solution found has the fewest moves.
    • Simple to implement and to explain: one queue, one visited set.

    Limitations

    • Memory grows as fast as time – every generated state is kept.
    • No sense of direction: it explores many states that move away from the goal.
    • Becomes impractical on larger puzzles (the 15-puzzle has about 1013 reachable states).

    Why BFS is optimal here (short argument)

    BFS removes nodes from the queue in non-decreasing order of depth. Suppose the shortest solution has d moves. Every node at depth d−1 is expanded before any node at depth d, so the goal is generated while expanding depth-(d−1) nodes, before any deeper node exists. Skipping a repeated state is safe because the copy already stored was reached at the same or a smaller depth. Since every move costs 1, fewest moves also means lowest path cost.

    Solvability check

    Write the tiles in reading order without the blank and count the inversions (pairs where a larger number comes before a smaller one). On a 3-wide board a left/right move does not change this order, and an up/down move makes one tile jump over exactly two others, changing the count by −2, 0 or +2. So the parity (odd/even) of the inversion count never changes. The initial state can reach the goal exactly when both have the same parity; the app checks this before searching.
